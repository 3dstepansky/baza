# Всё есть код

## Лекция на 20 минут о концепции «as Code» — и о том, является ли она тем, что ты ищешь

### 0:00 — Парадокс, с которого всё начинается

Самые сложные и надёжные рукотворные системы — глобальные облака, банковские платёжные контуры, спутниковые группировки — управляются текстовыми файлами. Это результат открытия: система, описанная как текст под контролем версий, становится управляемой; система, живущая в головах и на слайдах, — неуправляема.

### 2:00 — Генеалогия: боль, из которой родился Infrastructure as Code

Ручная настройка создавала уникальные серверы-«снежинки», знание о которых жило отдельно от самой системы. Infrastructure as Code сделала описание исполняемым: реальность стала результатом применения декларативного описания. Terraform описывает желаемое состояние, Kubernetes непрерывно сверяет его с фактическим и исправляет расхождение.

Показательный инцидент — Knight Capital в 2012 году. Компания потеряла около 440 миллионов долларов за 45 минут из-за сочетания неполного развёртывания на одном из восьми серверов, оставшегося старого кода и повторного использования управляющего флага. Это пример цены неконтролируемого расхождения конфигураций.

### 5:00 — Пять свойств as Code

1. **Декларативность** — описывается желаемое состояние, а не ручная последовательность действий.
2. **Версионность** — каждое изменение фиксируется; история позволяет восстановить состояние и автора решения.
3. **Изменение через ревью** — изменение оформляется как Merge Request: diff, обсуждение, одобрение и аудит.
4. **Автоматическая проверка** — целостность и политики проверяются до применения.
5. **Сверка и дрейф** — желаемое состояние непрерывно сравнивается с фактическим; расхождение становится рабочим событием.

Без петли сверки «as Code» рискует остаться лишь документацией в Git.

### 9:00 — Экспансия паттерна

Infrastructure as Code расширился в Configuration, Pipeline, Policy, Security, Docs, Data и Diagrams as Code. C4 Model Саймона Брауна дал четыре уровня семантического зума, а Structurizr — генерацию разных диаграмм из единой текстовой модели. DocHub и подход Architecture as Code применяют схожий жизненный цикл к архитектуре: декларативные манифесты, Git как источник правды, Merge Request и автоматическая валидация связей.

### 12:00 — Business as Code

Паттерн переносится на социотехническую систему: оргструктуру, роли, процессы, полномочия, информационные системы и AI-агентов.

- C1 — компания, окружение и контрагенты.
- C2 — домены и департаменты.
- C3 — роли людей и агентов, инструменты и делегирование.
- C4 — исполняемые артефакты: промпты, JSON-схемы, конфигурации навыков.

Git log становится историей изменений компании; управленческое решение — diff; линтер проверяет владельцев, контракты и целостность; телеметрия выявляет разрыв между заявленным и фактическим процессом.

AI сделал этот перенос экономически возможным с двух сторон: LLM ускоряет первичное извлечение модели из штатного расписания, вакансий и транскриптов, а агентам необходим машиночитаемый и проверяемый контекст для исполнения.

### 16:00 — Пределы метафоры

1. **Люди — не идемпотентные ресурсы.** Изменение манифеста не меняет поведение отдела автоматически; нужны управление изменениями, обучение и время.
2. **Дрейф двусторонний.** Иногда нужно привести реальность к манифесту, а иногда — обновить ошибочный манифест по доказательствам из реальности.
3. **Не всё оставляет цифровой след.** Доверие, неформальные связи, авторитет и выгорание остаются частично вне модели; карта не равна территории.

### 18:00 — Связь с Гелиосом

`as Code` — не отдельная шестая сущность модели Гелиоса, а носитель для уже найденных элементов:

- атом — задача с контрактом;
- шкала наивности — степень достоверности;
- слот — замена исполнителя при сохранении контракта;
- «было → стало» — эффект как разница состояний;
- счёт партии — агрегированная метрика территории человека и машины.

`as Code` отвечает, в какой форме модель хранится, проверяется, изменяется и не гниёт. Онтология Гелиоса отвечает, что является атомом, как измеряется достоверность, как устроено замещение и что считать экономическим эффектом.

**Итоговая формула:** Everything as Code — форма; онтология Гелиоса — содержание. По отдельности первое является пустым синтаксисом, а второе рискует стать быстро устаревающей философской схемой. Вместе они дают компанию, описанную в онтологии задач, с честной мерой незнания, читаемую агентами и изменяемую через контролируемый процесс.
