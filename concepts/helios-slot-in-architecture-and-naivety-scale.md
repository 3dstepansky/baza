# Слотовая архитектура замещения операций и шкала наивности бизнес-модели «Гелиос»

> Методология генеративного моделирования корпорации автономным агентом-архитектором, непрерывного уточнения бизнес-процессов по уровням наивности и бесшовного замещения человеческих операций слотами нейроопераций (Human Slot ➔ Neuro Slot).
> Источник идеи: [[raw/transcripts/telegram-helios-c4-enterprise-model-thoughtform-2026-09-07|Мыслеформа Павла о среде «Гелиос»]].

---

## 🏛 1. Агент единой цели: Генеративный архитектор предприятия

В среде [[entities/helios-agent-environment|«Гелиос»]] моделирование компании выполняет специализированный AI-агент, работающий в непрерывном цикле с единственной целевой функцией:

$$\text{Goal} = \arg\max \text{Fidelity}\Big(\text{C4-Ontology}(\text{Enterprise}) \mid \text{OrgStructure}, \text{HH}, \text{Transcripts}, \text{DWH}, \text{Finance}\Big)$$

Агент выполняет сквозное моделирование сверху вниз по принципу матрёшки:
1. **Корпорация / Холдинг** $\to$
2. **Департаменты / Домены** $\to$
3. **Штатная структура / Роли / Должности** $\to$
4. **Атомарные операции и контракты данных**.

---

## 📊 2. Шкала наивности и достоверности модели (Naivety & Confidence Scale)

Чтобы автоматизация не опиралась на галлюцинации и поверхностные предположения, каждый узел графа и каждый процесс размечаются **уровнем наивности**:

| Уровень | Наименование | Источники данных | Что известно модели | Готовность к автоматизации |
| :---: | :--- | :--- | :--- | :---: |
| **L1** | **Наивная оргструктура** | Штатное расписание, структура юрлиц, ERH-иерархия | Список отделов, штатные единицы, формальная субординация. | 🛑 Только скелет |
| **L2** | **Профиль обязанностей** | Парсинг HeadHunter (вакансии, стек, задачи), должностные инструкции | Ожидаемые функции сотрудника, требуемый стек ПО/систем, профили стейкхолдеров. | 🟡 Гипотезы процессов |
| **L3** | **Живая коммуникация** | Стенограммы встреч ([[entities/telemost-recorder|Яндекс.Телемост]]), интервью, рабочие чаты | Реальные сценарии работы, фактические коммуникации, исключения из правил и узкие места. | 🟢 Контекст и триггеры |
| **L4** | **Операционный факт** | DWH (хранилище данных), логи 1С/CRM, события YouGile/Jira | Точные контракты данных, частотность вызовов, тайминги, форматы входных/выходных структур. | 🚀 Готов к разработке агента |
| **L5** | **Финансовая оцифровка** | P&L центров затрат, ФОТ, стоимость человеко-часа | Экономический эффект (ROI) от замены операции, приоритет внедрения. | 💎 Максимальный приоритет |

## 🧬 3. Слотовая архитектура: Замещение человеческих операций (Human Slot ➔ Neuro Slot)

Ключевой принцип органического встраивания AI-агентов в компанию — **Slot-in Architecture**:

```
                              [ Бизнес-Процесс ]
                                      │
         ┌────────────────────────────┴────────────────────────────┐
         ▼                                                         ▼
[ Human Slot: До автоматизации ]             [ Neuro Slot: После автоматизации ]
• Исполнитель: Человек-специалист            • Исполнитель: AI-Агент «Гелиос»
• Вход: Документ / Заявка в CRM              • Вход: Тот же контракт данных (JSON/Schema)
• Выход: Решение / Запись в БД               • Выход: Тот же контракт данных (JSON/Schema)
• Стоимость: Высокая, скорость: часы         • Стоимость: Минимальная, скорость: секунды
• Контроль: Ручной                           • Контроль: Human-in-the-Loop (аномалии)
```

### Пример слотового манифеста (C3/C4 уровень)

```yaml
slot_id: slot.education.academic_diff.calculate
name: "Сверка учебных планов и расчет академической разницы"
domain: education_department
naivety_level: L4

execution:
  current_executor: human.role.academic_specialist
  target_executor: helios.education.academic_diff_agent
  status: candidate_for_neuro_slot

contracts:
  input:
    schema: AcademicRecordPayload
    sources: ["1C:Деканат", "Upload:PDF"]
  output:
    schema: RecreditProtocolPayload
    destinations: ["1C:Деканат", "Telegram:StudentNotification"]

metrics:
  human_cycle_time_min: 45
  neuro_cycle_time_sec: 3
  estimated_cost_reduction_percent: 94
```

## 🔍 4. Обогащение контекста из разнородных слоев данных

Иерархическая структура сама по себе недостаточна для понимания реальной жизни бизнеса. «Гелиос» объединяет несколько проекций:

1. **Структурная проекция (C1–C3):** кто кому подчиняется и где находятся центры ответственности.
2. **Рыночная проекция (HeadHunter):** какие навыки и задачи реально закреплены за позициями, какие технологии используются.
3. **Фактическая коммуникация (Телемост/Транскрипты):** неформальные лидеры, частые точки эскалации и трения.
4. **Транзакционная проекция (DWH):** реальный поток документов, заказов и задач в цифрах.
5. **Финансовая проекция (P&L):** где компания тратит больше всего ресурсов на рутинные клики и ручной ввод.
