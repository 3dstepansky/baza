Вайбкодерский рекрутинг — pipeline

Цель

Найти перспективных людей под постоянную офлайн-работу в офисе в Москве для корпоративных задач по вайбкодингу / AI automation.

Фокус ролей: - AI automation / agent workflows; - Telegram-боты; - API-интеграции; - MCP / OmniRoute / LLM tooling; - быстрые рабочие прототипы; - ресерч инструментов, но только если человек способен доводить до результата.

Важные правила коммуникации

  1. Не писать повторно людям, которые дали отрицательный ответ.
  2. Если человек ответил негативно — отметить status: rejected_by_candidate и не трогать по найму.
  3. Если человек заинтересован — вести короткий скрининг:
  4. интересен ли офис в Москве;
  5. есть ли GitHub/портфолио/примеры;
  6. какой стек;
  7. ожидания по формату/деньгам.
  8. Тестовые задания пока не предлагать и не обсуждать — сначала только интерес, офисный формат, стек, портфолио и базовые ожидания.
  9. Не писать в общие чаты с массовым наймом; сначала личные сообщения по индивидуальному сигналу.
  10. Ботов не считать кандидатами, но можно искать владельца, если бот интересный.

Статусы

  • new — найден, ещё не разобран.
  • shortlisted — есть тех/evidence сигнал.
  • contacted — написали первичное сообщение.
  • interested — ответил, что интересно.
  • screening — собираем портфолио/стек/условия.
  • promising — можно показывать Павлу.
  • rejected_by_candidate — человек отказался; не писать повторно по найму.
  • rejected_by_us — не подходит по рискам/качеству.
  • bot_artifact — бот/след к владельцу, не кандидат.

Ежедневный cron

Нужен ежедневный цикл:

  1. Расширить список чатов.
  2. Снять свежие сообщения за последние 24–48 часов.
  3. Найти авторов с полезными сигналами.
  4. Обновить мини-базу кандидатов.
  5. Не писать людям со статусом rejected_by_candidate / rejected_by_us / bot_artifact_risky.
  6. Подготовить daily digest для Павла:
  7. новые перспективные кандидаты;
  8. кто ответил;
  9. кому нужен follow-up;
  10. кого не трогать.
